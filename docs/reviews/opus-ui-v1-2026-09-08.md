## 通過：UNKNOWN 讀得出是刻意的

`.ruled` 的 `repeating-linear-gradient` ＋ 邊框 ＋ `min-height:120px` ——**把 `reserved for human judgment` 和 `✎ pencil` 兩行字刪掉,它仍然讀得出是一張等人填的表。** 形式自己撐住了,那就是驗收標準。

## 必修 ① `ref` 是寫死的假出處（最嚴重）

你的回報寫「每張卡:id + kind + note + sha + **ref**」。ref 確實印在畫面上,但:

```js
const prov = `<div class="prov">sha ${...} · ref frame:full</div>`;   // 寫死在模板
```

```
cases.json 裡 "ref" 出現次數：0
每筆欄位：expects_routing / fixture_id / kind / media / note / old_label / sha256
```

**每張卡都印同一句 `ref frame:full`,而資料裡沒有 ref 這個欄位。**

這比 `logging.py` 缺 ref 嚴重:那個是註解裡的主張,**這個是評審螢幕上看得到的假出處**。而 `route()` 的整條契約就建立在「沒有 ref 的觀察一律丟棄」——UI 印一個不存在的 ref,是把那條契約反過來演。

**二選一:** `cases.json` 每筆補真的 `ref` 並讀出來;或者**不要印**。不能寫死。

## 必修 ② CONFLICT 沒有顯示「哪裡對不上」

```js
<div class="side"><h3>舊標籤 old claim</h3><div>${c.old_label}</div></div>
<div class="side"><h3>所見 observed</h3>${media}</div>
```

左邊一句文字、右邊一張圖——**那兩邊不可比,人得自己看圖去比。**

但程式**已經比完了**:`old.colour=red` vs `observed.colour=beige`,同欄位不等才路由成 CONFLICT。**UI 沒把那件事顯示出來。**

少的就一行:

```
colour ·  old claim: red   ·   observed: beige      ← 這一行才是 CONFLICT
```

沒有它,UI 的 CONFLICT 跟 hero 裡並排的兩張照片一樣不可讀——**而把 CONFLICT 從 hero 搬到 UI 的唯一理由就是「這裡文字看得懂」。**

## 必修 ③ 計數器每筆多算一個

```js
el.querySelectorAll('.card,.pair,.ruled').length + 1
```

- `UNKNOWN` 每筆 append `.card` **＋** `.ruled` → 兩個
- `CONFLICT` 每筆 append `.pair` **＋** `.card` → 兩個

**標題數字會是實際的兩倍。** 截圖裡的數字錯,跟這個專案處理過的每一個過期數字同一類。

## 建議：加一個 accent，只用在檯面

現在整個 UI **沒有 accent 色**,所有層級都靠 `--ink-3` 灰在撐——那是它讀起來平的主因,也是**抽屜區和檯面區看起來一樣**的主因。

Crystal 給的參考站(Mini 做的 `THE-PROMPT-SANG-ITSELF`)有一個:`--accent: #8b6f47`。而兩邊的紙色實質同色(`#f5f1ea` vs `#f4f1eb`),所以那不是換風格,是**補一個現在缺的層級**。

```
一個 accent，只用在 CONFLICT / UNKNOWN。抽屜區完全不用。
```

比換字體有效得多,而且是一行 CSS。

**紙色留著沒關係**——跟 hero 綁在一起是好事。**要當代的是互動層**:真的控制項、已經宣告但幾乎沒用到的 `--sans`、以及一個只代表「這個需要你」的顏色。

（另:`--serif: "Cormorant Garamond"` 不是系統字體,會 fallback 到 Times / Songti。註解寫「system font stacks only」略微超出實情,無害。)
